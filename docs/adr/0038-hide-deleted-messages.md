# 0038. 削除したメッセージを画面から消す（Slack と同じ。返信の残るスレッドの親だけ跡を残す）

- 状態: 採用
- 日付: 2026-09-19

## 背景

Phase 6.5 の確認のあとに、オーナーから「削除しました、の履歴はいるか。Slack では完全に消える」という指摘があった。
いまはチャンネルでもスレッドでも、削除したメッセージの位置に「このメッセージは削除されました」を出している（ADR 0012 の tombstone。`chat/timeline/messages-all-states.png`）。

削除の跡を出していた主な理由は、**引用付きの返信の参照先が消えたことを示すため**だった。引用付きの返信はスレッドに置き換えた（ADR 0036）ので、その理由はなくなった。

## 決定

- **画面からは消す**。チャンネルのタイムライン、スレッドのパネルの返信とも、削除したメッセージを並べない。
- **例外は、返信の残っているスレッドの親**。親を消すと返信の置き場所（「N 件の返信」の入口）がなくなるので、「このメッセージは削除されました」を残す（Slack と同じ）。
  返信も全部削除されたら、親の跡も出さない。スレッドのパネルでは、親は削除されていても出す（パネルの見出しにあたるため）。
- **API とデータは変えない**。削除は論理削除のまま、tombstone を `message.deleted` と `after_change_seq` の差分で届ける。
  別の端末や切断していたクライアントが「このメッセージが消えた」と知る経路なので、行ごと消すと、消したはずのメッセージが残り続ける（ADR 0014）。
- **サイドバーの最後の 1 行は、削除されていない最後のメッセージ**にする（オーナーと確認）。
  - サーバーは、ルーム一覧と 1 件の取得で、「チャンネルに出ていて削除されていない最後の行」をルームごとの相関サブクエリで引く。
    `rooms.last_channel_seq`（ADR 0036）はこのために持っていた位置なので、使わなくなって削除した。
  - クライアントは、最後のメッセージが削除されたら（イベントでも差分の取得でも）いったん空にして、ルームを取り直す。ひとつ前のメッセージは手元にあるとは限らないため。
- 「ここから未読」は、最初の未読が削除されていたら、次に出ているメッセージの前に出す（並べるものから外すので、そうなる）。

## 理由

- **Slack と同じにする理由**: 削除は「なかったことにしたい」操作で、跡が残ると会話の流れを途切れさせる。跡を残す理由（引用の参照先）がもうない。
- **スレッドの親だけ残す理由**: 親を消すと、返信を読む入口がチャンネルから消える。跡を残せば、スレッドの一覧からもチャンネルからも同じ場所で開ける。
- **API を変えない理由**: 上のとおり、tombstone は同期のためのもので、表示の都合で消せない。表示だけの判断をクライアントに閉じ込める。
- **サイドバーの問い合わせを相関サブクエリにした理由**: 削除はまれなので、部分インデックス（`messages_room_id_channel_seq_idx`）を新しい順に読めばほぼ 1 行目で止まる。
  位置を列（`last_channel_seq`）に持って削除のたびに更新する方法は、削除で 1 つ前を探す処理が結局要る。LATERAL にしなかったのは、sqlc が列を NULL にならないものとして扱うため。

## 検討した代替案

- **いまのまま（すべて跡を出す）**: 実装は要らないが、オーナーの判断で不採用。
- **スレッドの親も含めて完全に消す**: 返信はスレッドの一覧からしか開けなくなる。
- **API から tombstone を返さない（行を物理削除する）**: 同期で削除を知る経路がなくなる。
- **サイドバーは空にする**: クエリは変えずに済むが、Slack と見え方が違う（オーナーと確認して不採用）。

## 結果（トレードオフ）

- **未読のバッジと中身が合わないことがある**。未読数は削除したメッセージも数える近似（ADR 0002 / 0033 / 0036）なので、
  「未読 1」でも開くと何もないことがある。跡が見えなくなったぶん目立つ。正確にするには削除のたびに全員の未読を直す必要があり、O(1) でなくなるので受け入れる。
- **admin が他人のメッセージを消しても、周りからは何も起きていないように見える**（Slack と同じ）。
  オーナーが確かめたうえで、このままにした（2026-09-19）。Slack でもワークスペースの owner と admin は他のメンバーのメッセージを削除でき、跡は残らない。
  hibari の削除の権限（ADR 0012: admin 以上が、自分より下のロールの人のメッセージを消せる。DM では消せない）は変えない。
  「管理者が消したときだけ跡を残す」は、誰が消したかを持つ必要があるので、必要になったら別に決める。
- 1 ページ（50 件）に削除済みが混ざると、見えるメッセージがその分少なくなる。
- `chat/timeline/messages-all-states.png`（Claude Design 由来）には「削除済み」の状態が写っているが、実装では出さない。Claude Design 側も直す。
  `MessageItem` の削除済みの表示は、スレッドの親のために残す。
