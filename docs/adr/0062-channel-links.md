# 0062. 本文の `#チャンネル名` をチャンネルへのリンクにする（本文には `<#ULID>` で保存し、名前は読む側が引く）

- 状態: 採用
- オーナーの確認: 2026-09-24
- 日付: 2026-09-24

## 背景

オーナーの要望（2026-09-24）。本文に `#チャンネル名` と書いたら、そのチャンネルへ移るリンクにしたい（Slack と同じ）。

保存の形はオーナーと決めてある（2026-09-24）。Slack と同じく、`#` を打つとチャンネルの補完が出て、本文には ID のトークンで保存する。
あとで名前を変えてもリンクが切れないようにするため。「本文は `#general` の文字のまま、表示するときに名前で照合する」案は採らなかった（検討した代替案）。

いまの前提は次のとおり。

- 本文のトークンはメンションの `<@ULID>` / `<!channel>` / `<!here>` がある（ADR 0041）。入力欄では token モードの `MentionNode` になり、補完と手で打った `@ハンドル` の変換がある（ADR 0043、0052）。
- ルームの名前はワークスペースの中で一意（`rooms_workspace_id_name_idx`）。ただし空白や日本語を含められ、80 文字まで（`internal/chat/room.go`）。
- ルーム一覧の API（`GET /workspaces/{id}/rooms`）は、参加しているルーム（全種類）と、参加していない public ルームを返す（ADR 0011）。
  つまり Web は、**自分が読めるチャンネルの名前をすべて手元に持っている**。持っていないのは、参加していない private ルームと、削除されたルームだけ。
- 検索（ADR 0061）は本文そのものに索引を張っている。`<@ULID>` もそのまま入っている。

## 決定

### 1. 本文のトークンは `<#ULID>`

- `<#` + ルームの ID（ULID の 26 文字）+ `>`。Slack の `<#C123>` と同じ形にする。名前は本文に入れない（名前を変えたら古くなるため）。
- 指せるのは public / private のルームだけ。DM は指さない（補完に出さない）。
- 本文の書式の解釈（ADR 0051）に、メンションと同じ種類のインラインとして足す。コードの中（`` ` `` と ```` ``` ````）は解釈しない。
- **サーバーは変えない。** サーバーはメンションのトークンしか読まず、読めないトークンは文字として保存する（ADR 0041）。
  `<#ULID>` は知らせの宛先にも authz にも関わらないので、サーバーが解釈する理由がない。

### 2. 名前は読む側が、手元のルーム一覧から引く

- 表示するときに、ストアのルーム一覧（上の API）から ID で名前を引く。名前を変えたら、`room.updated` でストアが変わり、過去の本文のリンクも新しい名前になる。
- **サーバーはメッセージに名前を付けない**（メンションの `mentions` のようなものは作らない）。
  メッセージは Pub/Sub でルームの全員に同じものを送るので（ADR 0016）、受け取る人ごとに「読める private ルームの名前だけ」を付けることができない。
  手元の一覧から引けば、読めない private ルームの名前は最初から手元にないので、漏れようがない。

### 3. 見た目はメンションと同じチップ。押すとそのチャンネルへ移る

| 引けたか | 見た目 | 押すと |
|---|---|---|
| public ルーム | `#名前`。個人のメンションと同じチップ（`bg-primary-subtle text-primary`） | そのルームを開く（参加していなくても読める。ADR 0006） |
| 参加している private ルーム | `🔒名前`（`#` の代わりに鍵のアイコン。サイドバーと同じ） | そのルームを開く |
| アーカイブ済みのルーム | 上と同じ | そのルームを開く（読むだけの画面。ADR 0059） |
| 引けない（参加していない private、削除済み） | `#アクセスできないチャンネル`。チップにせず、`text-text-muted` の文字 | 押せない |

- チャンネルは「押せるもの」なので緑のチップにする（`tokens.md`）。個人のメンションと同じ見た目にそろえる（ADR 0043 決定 3 の追記）。
- 引けないときに ID をそのまま出さない。`<#01J8…>` は読めないうえ、private ルームがあることしか分からない文字列を出しても意味がない。
  参加していない private と削除済みは、手元の情報では見分けられないので、同じ文言にする。
- 行全体がリンクの所（スレッドの一覧。`interactive={false}`）では、メンションと同じく押せないチップで描く。

### 4. 入力欄は `#` で補完を出し、`@` と同じ作り

- 語の始まり（行の頭か空白の後ろ）で `#` を打つと、チャンネルの補完を出す。`@` の補完（ADR 0043 決定 2）と同じ箱・同じキー操作。
- 候補は **public ルームと、参加している private ルーム**（ルーム一覧のうち DM とアーカイブ済みを除いたもの）。
  並びは前方一致を先、そのあと部分一致。どちらも名前の順。最大 8 件。
- 選ぶと `#名前` のチップ（token モードのノード）が入り、書き出すと `<#ULID>` になる。`MentionNode` にトークンの種類を 1 つ足す（ノードは増やさない）。
- 手で打った `#名前` も、送るときにチャンネルに一致すればリンクにする（`@ハンドル` と同じ。補完を使わなくても同じ本文になるように）。
  名前には空白を含められるので、**`#` の後ろで一致するいちばん長い名前**を選ぶ。後ろが空白・句読点・文字の終わりのときだけ一致とみなす。
- 編集するときは、`<#ULID>` を引けたら `#名前` のチップに戻す。引けなければトークンの文字のまま残す（保存すると元のトークンに戻る）。

### 5. 平文にする所では `#名前` に置き換える

`<@ID>` を `@名前` に置き換えている所（ブラウザ通知の本文。ADR 0057）では、同じく `<#ID>` を `#名前` に置き換える。引けなければ `#アクセスできないチャンネル`。

## 理由

- **ID で保存する**: 名前を変えてもリンクが切れない。名前で照合する案だと、名前を変えた瞬間に過去の本文のリンクが全部ただの文字に戻る。
  チャンネルの名前はワークスペースの運用で変わる（`#雑談` → `#random`）ので、切れるのが例外ではなく普通に起きる。
- **名前をサーバーから返さない**: 読めない private ルームの名前を漏らさないことを、authz の追加なしに構造で保証できる。
  サーバーの変更がないので、メッセージの API・イベント・Pub/Sub の形は変わらない。
- **メンションと同じ作りにする**: 入力欄のノード、補完の箱、手で打った文字の変換、書式の解釈、チップの見た目がすべて既にある。
  チャンネルはトークンの種類が 1 つ増えるだけで、作りの違いを覚えなくてよい。

## 検討した代替案

- **本文は `#general` の文字のまま、表示するときに名前で照合する**: 作るのは軽い（入力欄に手を入れない）。
  ただ、名前を変えると過去のリンクが切れる。`#1` や `#TODO` のような文字も、同じ名前のチャンネルがあればリンクになる。オーナーの判断で採らない（2026-09-24）。
- **Slack の `<#C123|general>`（名前を添える）**: 名前を引けない人にも名前が見えてしまう（private の名前が漏れる）。古い名前が残るのも嫌う。
- **サーバーがメッセージに `channels`（名前の表）を付ける**: 決定 2 のとおり、受け取る人ごとに付け分けられない。
- **引けないときに `#` + ID の先頭を出す**: 読めず、押せず、何の手がかりにもならない。

## 結果（トレードオフ）

- 検索で `general` と打っても、`<#ULID>` で書かれた `#general` には一致しない。メンションの `<@ULID>` と同じ制約（ADR 0061）。
- 参加していない private ルームへのリンクは、名前が分からない。書いた人と読む人で見え方が違う（Slack も同じ）。
- 削除したルームへのリンクは「アクセスできないチャンネル」になる。削除されたことは伝えられない。
- 手で打った `#名前` は、いちばん長い一致を選ぶ。`#デザイン` と `#デザインレビュー` があるとき、`#デザインレビュー` と打てば後者になる。
  `#デザイン レビューの件` のように空白で区切れば前者になる。
- ワークスペースのルーム一覧を読む前に描いた本文は、一瞬「アクセスできないチャンネル」になりうる（一覧はワークスペースを開いたときに読むので、実際にはほぼ起きない）。

## オーナーと確定した内容（2026-09-24）

下の 4 点はすべて案のまま採用。


1. private ルームのチップを `🔒名前`（鍵のアイコン）にする（決定 3）。`#名前` にそろえる案もある。
2. 引けないときの文言「アクセスできないチャンネル」（決定 3）。Slack は「プライベートチャンネル」と出す。
3. 補完にアーカイブ済みのルームを出さない（決定 4）。本文にすでにあるリンクは、アーカイブ済みでも押せる。
4. 手で打った `#名前` も変換する（決定 4）。補完から選んだときだけリンクにする案もある（打った文字が勝手に変わらない）。
