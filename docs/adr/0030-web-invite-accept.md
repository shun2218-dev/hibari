# 0030. Web の招待リンクの受け入れ（URL、ログインの振り分け、使えない招待の扱い）

- 状態: 採用
- 日付: 2026-09-18

## 背景

ロードマップ Phase 6-2 の「本番のページの構築順 6」の 2 本目（ADR 0029 で 3 つに分けたうちの 2 本目）。
招待リンクを開いたときの画面（`invite/accept-*.png`）をつなぐ。API は ADR 0006 / 0011 が決めている。決まっていなかったのは次のこと。

- リンクの URL の形（管理画面は `${origin}/j/{code}` を発行している。ADR 0029）
- プレビューが要ログイン（ADR 0011）なので、ログインしていない人をどう戻すか
- 使えない招待（取り消し・期限切れ・上限）と、それ以外の失敗の見せ分け

## 決定

### URL とログインの振り分け
- **`/j/{code}`。** コードは 22 文字の base64url（ADR 0011）なので、パスにそのまま置ける。
- ページは `app/(app)/j/[code]/` に置く。`(app)` のレイアウトがログインの振り分けを持っているので、
  ログインしていなければ `/login?next=/j/{code}` に飛び、ログインするとこの画面に戻ってくる（ADR 0024）。
- 招待リンクを持っていてアカウントがない人のために、**ログインの「アカウントを作成」も `next` を引き継ぐ**ようにした。

### 画面
- 認証と同じ外枠（`AuthShell`）に、カードの外の下に「別のアカウントで開きますか？ ログアウト」を出す（デザインどおり）。
  ログアウトすると `(app)` の振り分けが働き、`/login?next=/j/{code}` に戻る。
- **プレビューが返るまでは何も描かない。** 取得中の画面はデザインにない。
- 受け入れると、そのワークスペース（`/w/{id}`）に移る。手元のワークスペースの一覧にも足しておき、移った先で一瞬 0 件に見えないようにする。
- すでにメンバーなら「すでに参加しています」を出し、**受け入れの API を呼ばずに**開くだけにする（呼んでも成功するが、押さずに済むなら呼ばない）。

### 使えない招待
- `invite-invalid`（404）→ 無効、`invite-expired`（410）→ 期限切れ、`invite-exhausted`（410）→ 上限。
  どれもワークスペースの情報を出さない（サーバーも返さない。ADR 0011）。
- 存在しないコードが `not-found`（404）で返ることもあるので、**404 はすべて無効として扱う**。
- 見ている間にリンクが死んだとき（プレビューは成功したが受け入れで 410）も、同じ画面に切り替える。
- それ以外の失敗（通信の失敗、500）の画面はデザインにないので、何も描かずにコンソールに出す（ADR 0024 と同じ扱い）。

## 理由

- **`(app)` の中に置く理由**: プレビューも受け入れも要ログイン（ADR 0011）で、振り分けと ChatProvider（ワークスペースの一覧を更新する先）が
  すでにそこにある。招待のためだけの振り分けを書かずに済む。
- **`/j/{code}` にする理由**: 管理画面のデザイン（`hibari.app/j/•••••••`）がこの形を前提にしている。短いほど、チャットやメールに貼ったときに折り返しにくい。
- **404 をすべて無効にする理由**: 存在しない招待とワークスペースの存在を明かさない設計（ADR 0011）なので、クライアントから見て区別する意味がない。
- **すでにメンバーなら呼ばない理由**: 受け入れは冪等で安全だが、押していない操作をページを開いただけで送らない方が素直。

## 検討した代替案

- **招待のページを未ログインでも開けるようにする**: API が要ログイン（ADR 0011）で、`already_member` も返せない。
- **`/invite/{code}` や `/join/{code}`**: 動きは同じだが、デザインの `hibari.app/j/…` と合わない。
- **受け入れの後にワークスペースの一覧を取り直す**: 応答にワークスペースが入っているので、そのまま足せば 1 往復減る。

## 結果（トレードオフ）

- **招待リンクから登録した人は、登録の直後に「確認メールを送りました」の画面で止まる。** そこから招待に戻る導線がデザインにない
  （メールの確認は必須ではない。ADR 0010）。いまはもう一度リンクを開いてもらう必要がある（`docs/ui/README.md` の未解決）。
- 取得中と、通信の失敗・500 の画面がない。開いた直後は空白のカードに見える。
- 受け入れた直後に開くのは `/w/{id}` で、どのルームを開くかはチャットの画面が決める（ADR 0025）。招待で自動参加する `is_default` の
  ルームがなければ、「まだチャンネルがありません」になる。
