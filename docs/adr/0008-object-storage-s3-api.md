# 0008. オブジェクトストレージを S3 API で抽象化する

- 状態: 採用（本番のベンダーは **R2 に確定**。2026-09-20、ADR 0046）
- 日付: 2026-09-13

## 背景

添付ファイルを Phase 7 から Phase 3c に前倒しした。ストレージの候補は Amazon S3、Cloudflare R2、Vercel Blob など。
本番のベンダーは最終的に変える余地を残したいが、開発は今すぐ始めたい。

## 決定

- アプリケーションは **S3 API**（`aws-sdk-go-v2`）だけでストレージにアクセスする。実装は `internal/platform/storage` に閉じ込める。
- ローカル環境は **MinIO**（compose）を使う。
- 本番は **Cloudflare R2 を暫定の第一候補**とする。移行はエンドポイント・認証情報・バケット名の設定変更で済む状態を保つ。
  - **追記（2026-09-20、ADR 0046）**: 本決まりにした。決め手は egress が無料であることで、ファイルの中身をサーバーに通さない設計（ルール 10）では転送が全部ストレージから出るため。バケットは添付用と DB のバックアップ用の 2 つにする。
- ファイルの中身はサーバーを経由させない。
  1. クライアントがアップロードを要求する → サーバーが authz を行い、`attachments`（status = pending）を作り、署名付き PUT URL を返す
  2. クライアントがストレージに直接 PUT する
  3. クライアントが complete を呼ぶ → サーバーが HEAD でサイズと Content-Type を検証する
  4. メッセージ送信時に attached にする
  5. 閲覧時は、サーバーが authz を行い、短い TTL の署名付き GET URL を返す
- バケットは private にする。公開 URL は作らない。
- presigned PUT の署名には `Content-Length` と `Content-Type` を含める（R2 は presigned POST のポリシーによるサイズ制限に対応していないため、PUT の署名でサイズを縛る）。

## 理由

### 費用（2026 年 9 月時点の単価で試算）

| | R2 | S3 Standard（東京） |
|---|---|---|
| 保存 | $0.015 / GB・月（10GB 無料） | 約 $0.025 / GB・月 |
| 書き込み | $4.50 / 100 万回（100 万回無料） | 約 $4.7 / 100 万回 |
| 読み取り | $0.36 / 100 万回（1000 万回無料） | 約 $0.37 / 100 万回 |
| 転送（外への配信） | 無料 | 100GB/月の無料枠を超えると $0.114 / GB |

チャットの画像は「1 回アップロードして何度も閲覧される」ので、費用のほとんどが転送料になる。

| 想定 | R2 | S3（東京） |
|---|---|---|
| 学習用（10 人） | $0 | 約 $0.06 |
| 1,000 人（保存 100GB、転送 500GB） | 約 $1.4 | 約 $49 |
| 10,000 人（保存 1TB、転送 5TB） | 約 $19 | 約 $590 |

### S3 API にする理由
- R2、S3、MinIO、GCS（相互運用 API）、Backblaze B2 など、多くのサービスが S3 API に対応している。ベンダーの選定を先送りできる。
- ローカルで MinIO を使えるので、開発中にクラウドへの接続を必要としない。
- 署名付き URL による直接アップロードは S3 API の標準機能。

## 検討した代替案

- **Vercel Blob**: Private Blob と署名付き URL はあるが、SDK は JavaScript が中心で、ローカルのエミュレータもない。Go から扱う部分を自前で実装することになり、Next.js の Route Handler にロジックが寄りやすい（CLAUDE.md の禁止事項に抵触する）。
- **Amazon S3（本番）**: IAM やライフサイクルなど、実務で使う知識が得られる。ただし転送料で、規模が大きくなるとコストが桁違いになる。学習目的で S3 を選び直す余地は残る。
- **サーバー経由のアップロード（マルチパートを Go で受ける）**: 実装は単純だが、帯域とメモリをサーバーが負担し、水平スケールと相性が悪い。

## 結果（トレードオフ）

- R2 の署名付き URL は S3 API 用のドメインでしか使えない（独自ドメインでは使えない）。ダウンロード URL のドメインは固定になる。
- R2 の S3 互換は完全ではない。使う機能は PUT / GET / HEAD / DELETE と署名付き URL に限定し、それ以外（オブジェクト ACL、presigned POST など）に依存しない。
- complete を呼ばれなかった pending の添付を掃除する定期ジョブが必要になる。
- 本番のベンダーを変えるときは、この ADR を「置き換え済み」にして新しい ADR を書く。

## 追記（2026-09-25、オーナーの確認）: ローカルと CI のストレージを MinIO から RustFS に替える

MinIO の公式のイメージが、Docker Hub（2026-09-11）に続いて quay.io（2026-09-24）からも取れなくなり、CI の Go のテストが起動の前に落ちるようになった。
MinIO はコミュニティ版の配布を段階的に終えていた（2025-10 に新しいイメージを出さなくなり、2026-02 にリポジトリをアーカイブ）。

### 候補を実物で比べた（2026-09-24）

各候補を起動し、`internal/platform/storage` の統合テスト（申告と違う大きさと Content-Type の PUT を 403 で拒む、HEAD、GET のヘッダーの上書き、冪等な削除）と、バケットの作成・バケットの CORS の設定・ブラウザと同じプリフライトを確かめた。
手元に残っていた MinIO でも同じものを流し、基準にした。

| 候補 | テスト | バケットの CORS | 起動の手間 | イメージ / メモリ | 備考 |
|---|---|---|---|---|---|
| MinIO（基準） | 通る | 設定できず、すべてのオリジンを許す | — | — | イメージが取れない |
| **RustFS 1.0.0** | 通る | 設定できる | 環境変数だけ | 355MB / 120MB | Apache 2.0。MinIO の置き換えを目指す。利用者が多く開発が活発。1.0 が出たばかり |
| Versity Gateway v1.8.0 | 通る | 設定できる | 引数だけ | 93MB / 16MB | Apache 2.0。最小の構成。利用者は少なめ |
| MinIO のコミュニティ版（`pgsty/silo`） | 通る | 設定できない | 今と同じ | 199MB / 140MB | AGPL。第三者 1 社による派生版 |
| SeaweedFS 4.47 | 通る | 設定できる | 設定ファイルが要る | 693MB / 160MB | 起動が遅く、ログが多い |
| Garage v2.4.1 | 通る | 設定できる | 起動のたびに配置と鍵の登録が要る | 95MB / 7MB | AGPL。鍵の形式が決まっている |
| LocalStack 2026.08.4 | — | — | アカウントの認証トークンが必須 | 1.9GB | 使えない |

### 決定

- **ローカル（compose）と CI は RustFS にする**（オーナーの判断）。hibari が使う機能はどの候補も満たしたので、利用者の多さと将来の選択肢（複数台への分散など、本番のストレージにもなりうる）で選んだ。
- **イメージの版は固定する**（`rustfs/rustfs:1.0.0`）。変化が速いので、上げるときはストレージの統合テストで確かめる。
- **compose のサービス名は `s3`、環境変数は `LOCAL_S3_*` にする。** 製品名を名前に入れない。また替えるときに、server の設定とテストの接続先を変えずに済む。
- **バケットの作成は S3 の CLI を使わず、`curl --aws-sigv4` で S3 API を直接呼ぶ**（compose の `s3-init` と CI）。ストレージの製品の CLI に依存しない。
- **開発用のバケットにも CORS を設定する**（許すのは `APP_BASE_URL` からの PUT / GET だけ）。
  MinIO はすべてのオリジンを許していたので、本番の R2 で要る CORS の設定漏れに手元で気づけなかった（ADR 0013 の「結果」）。いまは手元でも、許していないオリジンのプリフライトは 403 になる。
- コード（`internal/platform/storage`）は変えない。S3 API だけを使っているので、ストレージを替えても同じ経路で動く（この ADR の決定のとおり）。
