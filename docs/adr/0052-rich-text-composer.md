# 0052. リッチテキストの入力欄（Phase 6.10b。Lexical を使い、読み書きは ADR 0051 の解釈と自前の書き出しで行う）

- 状態: 提案
- 日付: 2026-09-21

## 背景

Phase 6.10a（ADR 0051）で、本文を mrkdwn 寄りの記法のテキストで保存し、表示のときに解釈するようにした。
入力欄はまだ textarea で、書式は記号を手で打つしかなく、打った記号がそのまま見えている。

Phase 6.10b は、入力欄をリッチテキストにし、書いている途中から書式が見えるようにする（Slack と同じ）。
ADR 0051 決定 7 で、**6.10b は ADR 0051 の記法を書き出し、保存の形を変えない**と決めてある。

いまの入力欄（`Composer` とメッセージの編集欄 `MessageEditor`）が持っている機能:

- 文字列の `value` を受け取り、変わるたびに `onChange` で返す。下書きは画面の `useState`（`room-view.tsx` / `room-thread.tsx`）
- 入力欄ではメンションを `@handle` で書き、送る直前に `toWireBody` でトークン（`<@ULID>`）に変える。編集を始めるときは `toInputBody` で戻す（ADR 0043）
- `@` の補完。textarea では文字の座標を測れないので、候補は入力欄の左上に固定で出す（ADR 0043）
- Enter で送信、Shift + Enter で改行。IME の変換中は Enter を拾わない
- 中身に合わせて伸び、16 行（`--composer-max-lines`。ADR 0048）を超えたらスクロールする
- 送信ボタンの可否は、本文の長さの上限（`MAX_BODY_LENGTH`）と添付の状態で決める

オーナーと確定した内容（2026-09-21）:

- ライブラリは **Lexical**
- 入力の補助は **ツールバー + ショートカット + 記号の入力**（`*太字*` と打つとその場で太字になる）

### ライブラリの比較（2026-09-21 時点）

| | Lexical | Tiptap（ProseMirror） | Quill 2 | Slate |
|---|---|---|---|---|
| 版 | 0.51.0（2026-09-21。1.0 前） | 3.31.3（安定版） | 2.0.3（2025-01 から更新なし） | 0.126（1.0 前） |
| 大きさ（gzip。最小構成を esbuild で計測） | 約 122〜136KB | 約 123KB | — | — |
| 保存の形との噛み合い | 変換を自分で書く前提の作り（Markdown の変換ルールも差し替えられる） | 公式の Markdown 変換は CommonMark 前提 | Delta 形式 | 変換を自分で書く |
| 日本語の IME | 分けられない部品（メンション）の途中で変換を始めたときの修正まで入っている | 成熟しているが、複数行を選んで入力する不具合などが開いている | — | 不安定な報告が多い |

以前のメモの「Lexical は約 90KB で最軽量」は、いまは当てはまらない。Tiptap とほぼ同じ大きさで、大きさは決め手にならない。

## 決定

### 1. Lexical を使い、1 か所に閉じ込める

- `lexical` と `@lexical/react`・`@lexical/rich-text`・`@lexical/list`・`@lexical/history` を使う。
  **版は固定する**（`^` を付けない）。1.0 の前で、マイナー版でも破壊的変更がある（0.51 で ESM のみになった、など）。
- Lexical を import するのは `web/components/chat/editor/` の中だけにする。入力欄とメッセージの編集欄は、ここの `RichTextInput`（仮）を使う。
  版を上げるときに直す範囲をこのディレクトリに限るため。
- `@lexical/markdown` の読み書きは使わない（決定 2）。記号の入力（決定 5）にだけ使うかは、構築順 3 で実物を試して決める。

### 2. 読み込みは ADR 0051 の解釈、書き出しは自前の関数で行う

```
本文（ADR 0051 の記法のテキスト）
   │ 読み込み: parseBody（body-format.ts）の木 → Lexical のノード
   ▼
入力欄（Lexical の状態）
   │ 書き出し: Lexical のノード → 本文のテキスト（自前）
   ▼
本文（送る・下書きに持つ）
```

- **読み込みには 6.10a の `parseBody` をそのまま使う。** 表示と入力欄で同じ解釈を使えば、「表示では太字なのに、編集を開くと記号が見える」がない。
  `@lexical/markdown` は記法（境界の規則、` ``` ` の対、リストの字下げ）が ADR 0051 と違うので、読み書きに使うと 2 つ目の解釈になる。
- **書き出しは自前の関数にし、「書き出したテキストを `parseBody` で読むと、元の木と同じになる」をテストで保証する**（往復のテスト）。
- **ADR 0051 の記法で書けない書式は、書き出すときに落とす。** たとえば英単語の途中だけを太字にしたもの（`x*abc*y` は ADR 0051 の境界の規則で太字にならない）。
  記号を残すと、送ったあとに `*` がそのまま見える。書式が消える方が害が小さい。書式の前後の空白は記号の外に出す（`*abc *` ではなく `*abc* `）。

### 3. 入力欄の値は「送る形のテキスト」にする

- `Composer` の `value` / `onChange` は、**サーバーへ送る形のテキスト**（メンションは `<@ULID>` / `<!channel>` / `<!here>`）にする。
  下書きの `useState` と送信の処理はそのまま使える。**`toWireBody` / `toInputBody` は要らなくなる**ので消す。
- 入力欄は Lexical の状態を中に持つ。外から来た `value` を読み込み直すのは、**最後に書き出した値と違うときだけ**（送信後の空、編集の開始、ルームの切り替え）。
  打つたびに読み込み直すと、キャレットの位置と IME の変換が壊れる。
- 本文の長さの上限は、書き出したテキスト（送る形）の長さで判定する。サーバーの上限は保存される本文に掛かるため。

### 4. メンションは分けられない部品にし、補完はキャレットの位置に出す

- メンションは Lexical の中で**分けられないノード**（1 文字のように消える・選ばれる）にし、ユーザーの ID か全員宛ての種類を持つ。書き出しでトークンになる。
- 補完は `@lexical/react` の typeahead の仕組みで出す。contenteditable ではキャレットの座標が分かるので、**候補はキャレットの位置に出す**
  （ADR 0043 の「入力欄の左上に固定」は textarea の制約だった）。候補の並びと絞り込みは今の `filterCandidates` を使い回す。
- `@channel` / `@here` を送る前の確認（ADR 0043）は、書き出したテキストに対して今の `mentionAll` を使う。
- コードの中では `@` の補完を開かない（コードの中のトークンはメンションにならない。ADR 0051 決定 5）。

### 5. 入力の補助

- **ツールバー**: 太字・斜体・取り消し線・インラインコード・コードブロック・引用・箇条書き・番号付きリスト。
  **リンクのボタンは置かない**（ADR 0051 決定 4 で、表示する文字を URL と別にするリンクを持たないと決めた。URL は貼れば表示のときにリンクになる）。
  置き場所と見た目、モバイルでの出し方は構築順 2 のデザインで決める。
- **ショートカット**: 太字・斜体などのキーは、Slack の公式のショートカットの一覧に合わせる。具体的なキーは、デザインの段で公式の一覧を確かめてから決める（推測で書かない）。
- **記号の入力**: `*太字*` `_斜体_` `~取り消し~` `` `コード` `` を打つとその場で書式になる。行頭の `> ` `- ` `1. ` と ` ``` ` で引用・リスト・コードブロックになる。
  境界は ADR 0051 と同じ規則にする（`snake_case` と打っても斜体にしない）。
- **貼り付けはテキストとして入れる。** HTML を読み込まない（ADR 0051 の記法で書けないノードが入り込まず、見た目の差も出ない）。貼った文字の記号は解釈しない。

### 6. 送信と改行、16 行の上限

- **Enter で送信、Shift + Enter で改行**のまま（リストの中では次の項目、コードブロックの中では改行になる）。IME の変換中は Enter を拾わない。
  編集欄も今までどおり Enter で保存、Esc でキャンセル。
- 16 行の上限は、contenteditable の最大の高さを `--composer-max-lines` から決める（ADR 0048 のトークンをそのまま引き継ぐ）。

## 理由

- **Lexical にしたのは、保存の形との噛み合いと IME のため**（オーナーと確認。2026-09-21）。大きさは Tiptap とほぼ同じだった。
  Lexical は「エディタの状態を自分の形に書き出す」使い方が前提で、ADR 0051 の記法を書き出す部品にしやすい。
  メンションのような分けられない部品の途中で変換を始めたときの IME まで直しが入っているのは、日本語で使うチャットには大きい。
- **読み込みを ADR 0051 の解釈にしたのは、解釈を 1 つに保つため。** 6.10a で「本文から特別な部分を見つける仕組みを 1 つにする」を目標にした。
  入力欄が別の解釈を持つと、表示と編集で見え方がずれる。
- **値を送る形のテキストにしたのは、データ層を変えないため。** 下書き・送信・長さの判定・`@channel` の確認が、どれもテキストのまま動く。
  エディタの状態を上に持ち上げると、データ層が Lexical を知ることになる。
- **書けない書式を落とすのは、送ったあとに記号が見えるのを避けるため。** ADR 0051 にエスケープがないので、書ける範囲を超えたものは何かを失う。
  失うなら、読めない記号より書式の方がよい。
- **版を固定して 1 か所に閉じ込めるのは、1.0 前の破壊的変更に付き合う範囲を限るため。**

## 検討した代替案

- **Tiptap**: 成熟していて API も安定しているが、公式の Markdown 変換は CommonMark 前提で、mrkdwn では結局変換を自分で書く。
  日本語の IME の不具合の報告もいくつか開いている。オーナーと比較して不採用（2026-09-21）。
- **Quill 2**: Slack が使っているとされるが、2025 年 1 月から更新がない。Delta 形式は保存の形と噛み合わない。
- **`@lexical/markdown` で読み書きする**: 変換を書かずに済むが、記法が ADR 0051 と違い、解釈が 2 つになる。
- **エディタの状態（JSON）を下書きに持つ**: 下書きで見た目を完全に戻せるが、データ層が Lexical を知る。いまの下書きは画面の `useState` で、送れば消えるので、テキストで足りる。
- **ツールバーを置かない**: 見た目は今に近いが、記法を知らない人は書式に気づけない。オーナーと比較して不採用（2026-09-21）。
- **貼り付けで HTML を読み込む**: ほかのページから書式ごと写せるが、ADR 0051 で書けない書式（見出し・表・色）を落とす処理が要り、貼ったものと送ったものの見た目がずれる。

## 結果（トレードオフ）

- **1.0 前のライブラリに依存する。** 版を上げるたびに `components/chat/editor/` の直しが要りうる。
- **英単語の途中だけの書式は、送ると消える**（決定 2）。入力欄では見えているので、送った後に差が出る。
- **日本語の IME は jsdom で確かめられない。** 読み込み・書き出し・往復はユニットテストで厚く確かめるが、変換中の挙動は実物のブラウザで確かめる
  （E2E の Playwright は Phase 6 の予定で、まだ入っていない）。オーナーの実物での確認を DoD に入れる。
- **貼り付けた書式は消える**（決定 5）。
- バンドルが約 120KB（gzip）増える。チャットの画面でしか読み込まない。
- サーバー・API・WebSocket のイベント・ERD・`docs/events.md` は変わらない。保存の形は ADR 0051 のまま。
