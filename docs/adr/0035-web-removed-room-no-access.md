# 0035. 非公開チャンネルから外されたときは「アクセスできません」だけを出す

- 状態: 採用（ADR 0026 の「外されたとき」の非公開チャンネルと DM の部分を置き換える）
- 日付: 2026-09-19

## 背景

ADR 0026 では、開いている非公開チャンネルから外されたら、サイドバーとヘッダーを残して本文を「このチャンネルから外されました」にし、
「『{名前}』のメンバーではなくなったため、以降のメッセージは表示されません。」と説明していた（Claude Design の `chat/room/removed-from-channel.png`）。
一覧からは、ほかのルームを開くまで消さなかった。

実際に外される側を触ったオーナーから、次の指摘があった（2026-09-19）。

- 非公開チャンネルは、**名前も含めて**メンバーだけのもの。読めなくなった人に名前を出し続けない
- 「外された」とわざわざ言う必要はない。単にアクセス権がない、という見せ方でよい（Slack と同じ）
- 開いていたチャンネルも、サイドバーから即座に消してほしい（リロードするまで残っていた）
- URL で読めないチャンネルを開いたとき（これまでは黙ってワークスペースの入口に戻していた）も、同じ画面に揃える

## 決定

- 開いている非公開チャンネル（と DM）から外されたら、**本文を「このチャンネルにはアクセスできません」
  「チャンネルが存在しないか、閲覧する権限がありません。」にする**。操作は「チャンネル一覧に戻る」のまま。
- **ヘッダーごと出さない**（名前・人数・設定・メンバーのボタン）。開いていたメンバーのパネルも閉じる。
- **サイドバーからは、開いていてもすぐに消す**。一覧を取り直したときに残す処理もやめた。
- **URL で読めないルームを開いたとき（404）も同じ画面にする**。黙って入口に戻さない。覚えている場所（ADR 0025）からは外す。
- ストアの `removedRooms` は、開いている間だけ「読めなくなった」を覚えておくためにだけ使う（離れたら忘れる。これまでと同じ）。
- 変えないもの:
  - public ルームは参加していなくても読めるので、これまでどおり「参加する」の状態に戻すだけ
  - 自分で抜けた（`reason: left`）ときは、これまでどおりお知らせを出さずに入口に戻す（ADR 0034）
  - ワークスペースからのキック（`chat/workspace/removed-from-workspace.png`）。ワークスペースの名前は、キックされた人も招待を受けた時点で知っているので伏せない
  - 残ったメンバーが見るシステムメッセージ「{名前} がチャンネルから外されました」（ADR 0033）

## 理由

- **名前を出さない理由**: API は、読めない非公開ルームを「存在しない」と区別しない（404。ADR 0011）。
  画面だけが名前を出し続けると、この原則と食い違う。外された時点で、その人はもうメンバーではない。
- **「外された」と言わない理由**: 文言を「存在しないか、権限がない」にしておけば、URL を開き直したとき（404）と同じ意味になり、
  外されたのか、チャンネルがなくなったのかを本人に説明し分ける必要がない。Slack もこの形。
- **画面を出す理由（黙って入口に戻さない理由）**: 読んでいる最中に本文が消えて別のチャンネルに飛ぶと、何が起きたか分からない。
  リンクから開いたチャンネルが読めないときも同じで、黙って別のチャンネルが開くと、リンクが間違っていたのかどうかも分からない。
  自分で抜けたとき（ADR 0034）は本人の操作なので黙って戻してよいが、それ以外は何か一言が要る。
- **起動時にこの画面から始まらない理由**: 入口（`/`）はワークスペースまでしか決めず、ルームはサーバーが返した読めるルームの一覧の中からだけ選ぶ
  （最後に開いたルームも、一覧になければ使わない）。この画面に来るのは、URL を直接開いたときだけ。
- **すぐに一覧から消す理由**: ADR 0026 で残していたのは、お知らせに名前を出していたので、どのチャンネルの話かを一覧でも示すため。名前を出さないなら残す理由がない。

## 検討した代替案

- **ヘッダーは残して名前だけ伏せる**: 人数・設定・メンバーのボタンが残り、押しても何もできない。何のチャンネルかも分からないヘッダーは役に立たない。
- **お知らせを出さずに入口へ戻す**（これまでの URL で読めないルームを開いたときと同じ）: 上記のとおり、何が起きたかが伝わらない。
- **トーストで「アクセスできなくなりました」と出して入口へ戻す**: トーストの部品もデザインもない。新しい部品を作るより、既存の中央のお知らせで足りる。

## 結果（トレードオフ）

- `chat/room/removed-from-channel.png` は Claude Design の画面ではなく、実装から撮り直したものになった（ADR 0032 の撮り方）。Claude Design 側も直す。
- ヘッダーがないので、モバイルではヘッダーの「戻る」もなくなる。お知らせの「チャンネル一覧に戻る」で戻る。
- 存在しないルームの URL でも同じ画面になる（区別しないのは意図どおり）。通信の失敗（404 以外）はこれまでどおり何も出さない（ADR 0025 の未解決）。
