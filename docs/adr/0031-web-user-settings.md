# 0031. Web のユーザー設定（プロフィール・アバター・デバイス・テーマ）

- 状態: 採用
- 日付: 2026-09-18

## 背景

ロードマップ Phase 6-2 の「本番のページの構築順 6」の 3 本目（ADR 0029 で 3 つに分けたうちの最後）。
`settings/*.png` の画面をつなぐ。API は ADR 0019（セッションの一覧と失効、プロフィールの更新）と ADR 0020（アバター画像）が決めている。
決まっていなかったのは次のこと。

- URL と、モバイルの項目の一覧（`settings/mobile-list.png`）をデスクトップでどう扱うか
- User-Agent から「Chrome · macOS」のような表示を作る規則と、「2分前」「昨日 18:24」の書き分け
- アバター画像のアップロードを、添付（ADR 0028）と同じ仕組みにするか
- テーマをどこに持ち、いつ当てるか
- 表示の密度（値がデザインにない。`docs/ui/README.md` の未解決）をどうするか

## 決定

### URL
- **`/settings/{profile|devices|appearance}`**、入口は `/settings`。要ログインなので `app/(app)/` の中に置く。
- `/settings` はモバイルの項目の一覧を描き、**md 以上（左にナビが出る幅）ではプロフィールに移る**。
  一覧と左のナビは同じものなので、デスクトップで一覧だけの画面を見せない。
- アカウントメニューの「設定」は `/settings` を開く（モバイルは一覧、デスクトップはプロフィール）。

### プロフィール
- 表示名とハンドルは、**入力中だけ手元の値を使い、フォーカスを外したらサーバーに送る**（ワークスペースの名前と同じ形。ADR 0029）。
  送り終えたら手元の値を捨て、応答の user で画面を進める。失敗しても画面と DB がずれない。
- ハンドルの重複（409）や入力のエラー（422）の表示はデザインにないので、値を戻してコンソールに出す。

### アバター画像
- 添付（ADR 0013 / 0028）と同じく **発行 → ストレージへ直接 PUT → complete** の 3 段。PUT は `lib/chat/put-file.ts` を使い回す。
  中身は Go サーバーも Next.js も経由しない（CLAUDE.md ルール 10）。
- 進み具合はデザインにない（アップロード中の表示だけ）ので、`onProgress` は捨てる。取り消しの導線もないので、打ち切りは行わない。
- **種類と大きさをクライアントで検査しない。** ファイルの選択は `accept` で PNG / JPEG / WebP に絞るが、通ってしまったものは発行の 422 で落とす。
  上限（既定 2 MiB）はサーバーの設定値（`AVATAR_MAX_BYTES`）なので、同じ値を手元に持たない（ADR 0028 の許可リストと同じ考え方）。
- 失敗したら「アップロードできませんでした」と再試行（同じファイルで発行からやり直す）。理由は出さない（デザインにない）。
- 削除は `DELETE /users/me/avatar`。応答の user で頭文字の表示に戻る。

### デバイスの一覧
- User-Agent の解析と時刻の文言はクライアントで作る（ADR 0019）。`lib/auth/devices.ts` にまとめ、当たらなければ User-Agent をそのまま出す。
  - Edge / Chrome の派生は Chrome を名乗るので先に見る。iPad / iPhone は「like Mac OS X」を名乗るので macOS より先に見る。
  - ネイティブアプリ（Phase 7 以降）は `hibari/1.2.0 (iOS 18; iPhone 15)` の形を想定し、「hibari for iOS · iPhone 15」にする。
- 最後に使った時刻は、デザインにある例（「現在アクティブ」「2分前」「昨日 18:24」「3日前」「9月2日」）から、
  **1 時間未満は分、同じ日は時刻、前日は「昨日 時刻」、1 週間以内は日、それより前は日付**とした。
  文言は**画面を開いた時点の時刻**で決め、開いたまま時間が経っても書き換えない。
- 失効は手元の一覧からその行を消すだけで、取り直さない。失敗したときだけ取り直す。

### テーマ
- **`<html data-theme>` を正とし、値は localStorage（`hibari:theme`）に置く。** 端末ごとの見た目の好みなので、サーバーには持たない。
  OS の設定には追従しない（CLAUDE.md「デザイン」）。
- ルートのレイアウトの `<head>` に 1 行のスクリプトを置き、**最初の描画の前に当てる**。React の描画を待つと、ダークにしている人に一瞬ライトの画面が見える。
- 画面は `useSyncExternalStore` で購読する（session / chat のストアと同じ形）。読み書きに失敗しても、その画面の見た目だけは変える。

### 表示の密度
- 行送りと余白の値がデザインにないので、**選択肢は出すが選べないようにした**（`AppearanceSettings` に `densityLocked` を足し、既存の無効なラジオの見た目を使う）。
  値が決まったらトークンを足して外す。

## 理由

- **デスクトップで一覧を出さない理由**: 左のナビに同じ項目が並ぶ。`/settings` に何も出さないより、最初の項目を開く方が迷わない。
- **入力をフォーカスの離脱で確定する理由**: デザインに「保存」ボタンがない。ワークスペースの設定と同じ扱いにそろえた。
- **クライアントで大きさを検査しない理由**: 上限はサーバーの設定値で、二重に持つとずれる。選んだ直後に落ちるか、発行で落ちるかの違いしかない。
- **テーマを DOM から読む理由**: 最初の描画の前にスクリプトが当てているので、DOM がいちばん新しい。localStorage を毎回読むと、
  値が同じでも `useSyncExternalStore` に新しい文字列を返しうる形になりやすい。
- **時刻の文言を開いた時点で固定する理由**: 一覧が勝手に「2分前 → 3分前」と書き換わっても意味がなく、タイマーを持つ理由がない。

## 検討した代替案

- **テーマをサーバー（users の列）に持つ**: 端末ごとに変えられなくなり、API とマイグレーションが要る。見た目の好みは端末の設定でよい。
- **OS の設定（`prefers-color-scheme`）に追従する**: CLAUDE.md が「追従しない」と決めている。
- **User-Agent の解析をサーバーで行う**: ADR 0019 で「表示の都合で変わるのでクライアント」と決めている。
- **アバターのアップロードに `lib/chat/uploads.ts` を使う**: あちらは「入力欄に並ぶ複数の添付」を扱うストアで、1 枚の差し替えには重い。
- **密度の選択肢を画面から消す**: デザイン（`settings/appearance.png`）にあるものを消すことになる。無効にして残す方が、デザインとの差が小さい。

## 結果（トレードオフ）

- 失敗の理由が出ない（ハンドルの重複、画像が大きすぎる・種類が違う、セッションの取得の失敗）。`docs/ui/README.md` の未解決に記録した。
- **設定の画面からチャットに戻る導線がない**（モバイルの項目の一覧にも、デスクトップにもない）。管理画面と同じ抜けで、デザイン待ち。
- 表示の密度は選べない。
- アバターのアップロードは取り消せない（画面を離れても PUT は続く）。1 枚 2 MiB までなので、打ち切りの仕組みは持たない。
- テーマはタブごとではなくオリジンごと（localStorage）。同じブラウザの別のタブは、次に開いたときから新しいテーマになる。
- ブラウザでの確認は、ローカルの compose に対して行った（表示名の変更、画像のアップロードと削除、デバイスの一覧、ダークテーマの切り替えとリロード）。
