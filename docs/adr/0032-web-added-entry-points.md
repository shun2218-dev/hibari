# 0032. デザインに足した入口（DM・チャンネルの設定・チャットに戻る）と、実装から撮るスクリーンショット

- 状態: 採用
- 日付: 2026-09-19

## 背景

Phase 6-2 の構築順 6（ADR 0029 / 0030 / 0031）で、**API と画面はあるのに入口がない**ものが 4 つ見つかり、
`docs/ui/README.md` の「未解決」に挙げてオーナーの判断を待っていた。

- サイドバーに DM を始める入口がない（`chat/room/dm-dialog.png` はある）
- ルームのヘッダーにチャンネルの設定を開く入口がない（`chat/room/room-settings-dialog.png` はある）
- チャンネルの設定の「メンバーを追加」を押した後、相手を選ぶ画面がない
- 管理画面と設定から、チャットに戻る導線がない（モバイルのヘッダーの「戻る」だけ）

オーナーと確認して、**これまでと同じやり方（既存の部品とトークンのまま描いて `docs/ui/` に足す）で先にデザインを足し、
そのうえでつなぐ**ことにした。決めることは、足す画面の形と、スクリーンショットの撮り方の 2 つ。

## 決定

### 足した入口

| 画面 | 決めたこと |
|---|---|
| サイドバー | セクションの見出し（「チャンネル」「ダイレクトメッセージ」）の右に「+」を置く。片方が 0 件でも見出しと「+」は出す（DM が 1 件もないときに入口が消えないように）。ルームが 0 件のときは一覧ごと出ないので、`chat/room/empty-rooms.png` の「チャンネルを作成」のボタンはそのまま残す |
| ルームのヘッダー | 「メンバー」の左に設定（歯車）のボタン。**DM では出さない**（設定を変えられない。ADR 0011）。member にも読み取り専用で開ける |
| メンバーを追加 | DM の相手を選ぶ画面と同じ形（検索 + ひとり選ぶ）。候補は、すでにそのチャンネルにいる人と自分を除いたワークスペースのメンバー |
| チャットに戻る | 管理画面と設定の左のナビの上（デスクトップ）と、設定の一覧のヘッダー（モバイル）。管理画面のモバイルは、これまでどおりヘッダーの「戻る」がチャットに戻る |

設定はワークスペースに属さないので、戻り先は入口（`/`）にする。最後に開いた場所が開く（ADR 0025）。

### スクリーンショットの撮り方

`docs/ui/screenshots/` の元は Claude Design の `.dc.html` を headless Chrome で描画したもので、それは変わらない。
**実装の側から足した画面（Phase 6-1 以降の追加分）は、`/dev/preview` を headless Chrome で撮る**ことにし、
手順を `tools/shoot-ui.mjs`（`make web-shots`）にした。

- 名前は `/dev/preview` のカタログと同じ「グループ/名前」。カタログとスクリーンショットの 1 対 1 は既存のテストが検査する。
- 大きさは既定で 1280×800、`mobile-` で始まる名前は 390×844、`名前:WxH` で部分を切り出したフレームも撮れる。
- Next.js の開発インジケータは `HIBARI_SCREENSHOTS=1` で消す（`next.config.ts`）。
- **`--window-size` + `--screenshot` は使わない。** 幅が狭いときに、横に伸びるはずの要素が縮んだ状態で描画された
  （設定の一覧の「>」が消える）。DevTools Protocol の `Emulation.setDeviceMetricsOverride` で幅を決めてから撮る。

**追記（2026-09-20）: 一覧（`/dev/preview`）に検索・フェーズの絞り込み・グループの畳みを足した。**

画面が 120 件を超え、1 ページに全部並べると探せなくなったため（オーナーの指摘）。

- **手を入れるのは一覧だけ。個別の画面（`[...name]`）には枠を足さない。** `shoot-ui.mjs` がそのページを
  原寸で撮るので、サイドバーやヘッダーを足すと `docs/ui/screenshots/` が変わってしまう
- カタログの各行に「どのフェーズで足したか」（`since`）を持たせ、チップで絞れるようにした。
  値は `docs/ui/README.md` から機械的に決める（取り込みの表にある画面は `1.5`、
  以降の「…で足した画面」で初めて出てくる画面はそのフェーズ）
- グループは既定で畳み、検索やフェーズで絞っている間は開いたままにする。`/` で検索欄に入り、Esc で条件を捨てる
- **fumadocs や Storybook は入れない**（下の「検討した代替案」）

## 理由

- **見出しの「+」にした理由**: サイドバーに新しい行や固定のボタンを足すより、増やす対象（チャンネル / DM）の隣に置いたほうが、
  何が増えるのかが分かる。既存の `IconButton` とトークンだけで描ける。
- **0 件でも見出しを出す理由**: DM が 1 件もない人に入口がなくなる。実際、つないだ後にその状態になって気づいた。
- **DM に設定を出さない理由**: DM は名前もメンバーも変えられない（ADR 0011）。押せるのに何もできないボタンを出さない。
- **実装から撮る理由**: この 4 つは Claude Design のキャンバスにない画面で、コード側にしか存在しない。撮り方を決めておかないと、
  「デザインを変えたら撮り直す」が実行できない。撮り直しをスクリプトにして、誰でも同じ手順で撮れるようにした。
- **CDP を使う理由**: 上記のとおり、`--window-size` では狭い幅のレイアウトが正しく描かれなかった。原因を追うより、
  幅を明示して撮れる経路に替えるほうが確実。

## 検討した代替案

- **サイドバーの下に「+ 新規」の固定ボタンを置く**: どちらが増えるのかが分からず、チャンネルと DM で選ばせる 1 段が増える。
- **ルームのヘッダーではなく「…」のメニューに設定を入れる**: 項目が設定だけなので、1 段深くする意味がない。
- **メンバーの追加をメンバーパネルから行う**: パネルは表示専用（ADR 0018）で、public ルームでも開く。追加は非公開のチャンネルの設定にだけある操作なので、設定に置く。
- **既存のスクリーンショットをすべて `/dev/preview` から撮り直す**: 元が Claude Design の画面と実装の画面が混ざり、どちらが正本か分からなくなる。
- **一覧に fumadocs を入れる**（2026-09-20）: 検索とサイドバーが完成品で付くが、MDX のコンテンツサイト向けの土台で、
  ここは React 部品のカタログなので噛み合わない。`fumadocs-ui` は自前の Tailwind プリセットと CSS 変数を持ち込むので、
  **トークンの正本を `globals.css` だけにする規則（CLAUDE.md ルール 7）と衝突する**。欲しいのは 120 件の配列の
  絞り込みだけなので、自前で書いた。
- **Storybook に移す**（2026-09-20）: 部品カタログとしては本筋だが、`docs/ui/screenshots/` と 1 対 1 の名前・
  `shoot-ui.mjs` の撮影・カタログのテストがすべて Next.js のルート前提で組んである。ビルドがもう 1 つ増え、
  トークンの衝突は fumadocs と同じ。

## 結果（トレードオフ）

- **既存のスクリーンショット（Claude Design 由来）には、「+」「設定」「チャットに戻る」がまだ写っていない。**
  Claude Design 側を直したら撮り直す（`docs/ui/README.md` に明記した）。
- 実装から撮った 6 枚は、実装が変われば見た目も変わる。「デザインが正本」の原則から外れるので、Claude Design 側に取り込むまでの暫定とする。
- チャンネルの設定・DM・メンバーの追加の失敗（名前の重複、相手がワークスペースを抜けた）の表示はデザインにない。
  ほかの操作と同じく、ダイアログを残してコンソールに出す（`docs/ui/README.md` の未解決）。
- 表示の密度（`settings/appearance/appearance.png`）は、行送りと余白の値がまだない。選択肢は出したまま選べないままにしてある（ADR 0031）。
