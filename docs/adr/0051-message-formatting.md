# 0051. 本文の書式（Phase 6.10a。mrkdwn 寄りの記法をテキストのまま保存し、Web で解釈して React の要素で描く）

- 状態: 採用
- 日付: 2026-09-21

## 背景

Phase 6.10 は、本文に太字・斜体・取り消し線・インラインコード・コードブロック・引用・リストを書けるようにし、
URL をリンクにする（オーナーの要望。2026-09-20）。あわせて、本文から「特別な部分」を見つける仕組みを 1 つにする。

いまは「特別な部分」の解釈が 3 か所に散っている。

| 解釈 | 場所 | 使い道 |
|---|---|---|
| メンションのトークン（`<@ULID>` / `<!channel>` / `<!here>`） | `web/lib/chat/mentions.ts`（`splitBody`）と `internal/chat/mention`（`Parse`） | チップの表示（ADR 0043）と件数（ADR 0041） |
| パーマリンクの URL | `web/lib/chat/links.ts`（`findPermalinks`） | リンクのカード（ADR 0040） |
| それ以外 | なし | 本文はそのままの文字列として出している |

どちらのコメントにも「6.10 でこちらへ吸収する」と書いてある。ADR 0041 は、**コードブロックの中のメンションを除外するなら、
数える側（サーバー）も合わせる**ことを 6.10 の宿題にしている。

表示の場所も揃っていない。タイムラインは `MessageBody` でチップを出すが、スレッドの一覧（`thread-list.tsx`）と
リンクのカード（`message-link-card.tsx`）は本文をそのまま出しているので、メンションがトークンのまま見える。

オーナーと確定した内容（2026-09-21）:

- 記法は **Slack の mrkdwn 寄り**にする（Markdown のサブセットではない）
- フェーズを **6.10a（表示）と 6.10b（入力欄）に分ける**。6.10a で表示の解釈を作って DoD を満たし、
  6.10b で入力欄をリッチテキストにする（6.11 を a / b に分けたのと同じ入れ方）
- ADR 0050 の宿題（未検証の email のままチャットを使えること）は、6.10 の後に回す

この ADR は 6.10a の設計と、**6.10b の入力欄が書き出さなければならない保存の形**を決める。
6.10b の入力欄の作り方（ライブラリ、ツールバー、ショートカット）は 6.10b の ADR で決める。

## 決定

### 1. 本文はテキストのまま保存し、表示のときに解釈する

- `messages.body` はいままでどおりテキスト。**書式のための列も、エディタの JSON も持たない。**
- サーバーは本文をそのまま返す。`docs/events.md` の `body` の形は変わらない。
- 6.10b の入力欄は、送るときにこの ADR の記法のテキストへ書き出す。サーバーから見れば、textarea から来た本文と区別がつかない。

### 2. 記法（mrkdwn 寄り）

**ブロック**（行の単位）

| 書き方 | 意味 | 中を解釈するか |
|---|---|---|
| ` ``` ` と ` ``` ` で挟む | コードブロック | しない（書いたとおりに等幅で出す） |
| 行頭の `> ` | 引用。続く行も `> ` で始まれば同じ引用 | する |
| 行頭の `- ` / `* ` / `• ` | 箇条書き | する |
| 行頭の `1. `（数字 + `.` + 空白） | 番号付きリスト。番号は書いた値を出す | する |
| リストの行頭の空白 2 つ | 1 段深くする（3 段まで） | — |
| それ以外 | 段落。改行はそのまま改行として出す | する |

- コードブロックの ` ``` ` は行の途中でもよい（` ```x = 1``` ` の 1 行もコードブロック）。
  **閉じていない ` ``` ` はただの文字**として出す（途中まで打った本文や、畳んだ本文で表示が崩れないように）。
- 見出し・表・画像・水平線・生の HTML は持たない（チャットで要らない）。

**インライン**

| 書き方 | 意味 |
|---|---|
| `` `code` `` | インラインコード。中は解釈しない |
| `*太字*` | 太字 |
| `_斜体_` | 斜体 |
| `~取り消し~` | 取り消し線 |
| `__下線__` | 下線（下の「追記: 下線」） |
| `https://…` / `http://…` | リンク（決定 4） |
| `<https://…\|文字>` | 文字付きのリンク（決定 4 の「追記: 文字付きのリンク」） |
| `<@ULID>` / `<!channel>` / `<!here>` | メンション（ADR 0041。決定 5） |

- 太字・斜体・取り消しは入れ子にできる（`*_両方_*`）。インラインコードの中には何も入れられない。
- 1 つの書式は行をまたがない。閉じていない記号はただの文字として出す。
- **記号の前後の境界は「ASCII の英数字でないこと」にする。**
  開く記号の直前と、閉じる記号の直後が行頭・行末・空白・句読点・**日本語の文字**なら書式になり、ASCII の英数字なら書式にならない。
  開く記号の直後と閉じる記号の直前は空白であってはいけない。

  ```
  これは*太字*です          → 太字になる（日本語の文字は境界）
  snake_case_name           → ならない（_ の両側が英数字）
  2 * 3 * 4                 → ならない（* の直後が空白）
  ```

  空白を境界の条件にすると、日本語の文中（前後に空白を置かない）で書式が効かない。6.10b の入力欄は「文中の一部だけ太字」を
  書き出す必要があるので、日本語の文中で書式が効かない記法では、選んだ範囲を太字にした結果を保存できない。
- 記号そのものを書式にせずに出すエスケープ（`\*`）は持たない。書式にしたくなければインラインコードで囲む。

記法の正本は Web の解釈のテスト（テーブル駆動）にする。境界の規則はこの ADR にあるが、具体的な入力と結果の組はテストが持つ。

### 3. 解釈は Web で行い、React の要素で描く

- `web/lib/chat/format.ts`（仮）に、本文を**木**（ブロックとインラインの判別共用体）に分ける純粋な関数を 1 つ置く。
  メンションのトークンと URL も、この 1 回の走査で見つける。`splitBody` と `findPermalinks` の URL の走査はこれに置き換える。
- 描くのは木を React の要素に写すだけのコンポーネント（いまの `MessageBody` を置き換える）。
  **`dangerouslySetInnerHTML` を使わず、HTML の文字列も組み立てない。** 本文の文字はすべて React のテキストとして出るので、
  `<script>` などは文字のまま表示される。`design-rules.test.ts` で `web/components/chat` での `dangerouslySetInnerHTML` を禁じる。
- 解釈は自前で書く（ライブラリを使わない）。記法が mrkdwn 寄りで、境界の規則とメンションのトークンを持つので、
  Markdown のパーサー（remark / markdown-it）は設定で外す機能の方が多い。HTML の文字列を返すライブラリは決定 3 の描き方と合わない。
- 描く場所を 1 つにする。**タイムライン・スレッドのパネル・スレッドの一覧・リンクのカード**が同じ解釈を使う
  （いまトークンのまま見えているスレッドの一覧とカードもチップになる）。
  - スレッドの一覧は、いまの 2 行で畳む表示のまま、木を描いてから CSS で畳む。
  - リンクのカードは、**木を作ってからブロックの単位で畳む**。テキストを先に切ると、` ``` ` の対が壊れて閉じていない記号になるため。
    `clampCardBody` の「行数と文字数で決め、描画を待たない」（ADR 0040）はそのまま守る。
- 見た目（コードの地の色、引用の線、リストの字下げ）は構築順 2 のデザインで決める。
  等幅のフォントは既存の `--font-mono` を使う。新しいトークンが要るなら、デザインの段でオーナーに確認する。

### 4. URL のリンク

- `http://` と `https://` で始まるものだけをリンクにする。**`javascript:` などは、書き方にかかわらずリンクにしない。**
- URL は ASCII の空白以外の文字が続く間とし、日本語の文字・空白・`<` `>` で終わる。
  末尾の句読点と閉じ括弧（`.` `,` `)` `」` `。` など）は含めない（いまの `findPermalinks` と同じ規則を引き継ぐ）。
- `<a href target="_blank" rel="noopener noreferrer">` で別のタブに開く。
  **パーマリンク（ADR 0040）だけは同じタブで飛ぶ**（6.11b で作った飛ぶ仕組みに乗せる。いまも本文のリンクではなくカードから飛んでいる）。
- ~~表示する文字を URL と別にする書き方（Slack の `<url|text>`）は持たない。~~ → 持つ（下の「追記: 文字付きのリンク」）。
- コードの中の URL はリンクにせず、カードも出さない。

#### 追記: 文字付きのリンク（2026-09-21。オーナーの確認）

Phase 6.10b（ADR 0052）で、ほかのページから貼り付けた書式を残せるか検証した。`<a href="…">リンクの文字</a>` だけがこの記法で書けず、
文字か URL のどちらかを失う。Slack ではできることなので、**`<URL|文字>` を記法に足す**（Slack と同じ形）。

```
<https://example.com/docs|手順書>   → 「手順書」がリンクになる
```

- URL は `http://` / `https://` で始まるものだけ（上と同じ）。それ以外は文字付きのリンクにせず、ただの文字として出す。
- **文字には `<` `>` `` ` `` と改行を使えない。** 使っていたら文字付きのリンクにしない（`<` から先は普通の本文として読む）。
  サーバーはコードの範囲とメンションしか解釈しない（決定 5）ので、文字の中にバッククォートや `<` を許すと、
  「文字の中のバッククォートとその外のバッククォートでコードになる」「文字の中にトークンがある」といった読み方の違いで、
  サーバーと Web でメンションの数え方がずれる。この 2 つの例を `testdata/format/mentions.json` に入れて固定する。
- 文字の中は解釈しない（書式もメンションも入れない）。外側の書式の中には置ける（`*<URL|文字>*`）。
- 表示では文字をリンクにし、**URL をホバーで見せる（`title`）**。文字と行き先が違うリンクは、行き先を隠したなりすましに使えるため。
  別のタブで開く・パーマリンクは同じタブ、は URL のリンクと同じ。パーマリンクならカードも出す。
- サーバーは変わらない（トークンの正規表現は `<@` と `<!` だけを見る）。

#### 追記: 下線（2026-09-21。オーナーの確認）

Phase 6.10b（ADR 0052）のデザインの前に Slack の公式のヘルプを確かめると、書式のツールバーとショートカット（⌘U）に**下線**があった。
Slack でできることなので、**`__下線__` を記法に足す**。

- 境界の規則は斜体と同じ（`ここは__大事__です` は下線、`a__b__c` はならない）。行頭や空白の後に単独で書いた `__init__` は下線になるので、コードとして書くならバッククォートで囲む。
- 斜体の `_` を探すときは `__` を飛ばす（`_a __b__ c_` は「斜体の中の下線」）。
- いままで `__x__` は「`_` と斜体の x と `_`」と読まれていた。既存の本文でこう書いたものは、見た目が下線に変わる（テキストは変わらない）。
- サーバーは変わらない（`_` はコードの範囲にもメンションにも関わらない）。

### 5. コードの中のメンションは、表示も件数も除外する（ADR 0041 の宿題）

- **コード（インラインとブロック）の中のトークンはメンションではない。** Web はチップにせず文字のまま出し、
  **サーバーも件数（`message_mentions`）と `@here` の解決と `mentions` の応答から外す。**
  表示と件数がずれると「通知は来たのに本文のどこにもメンションがない」が起きる。
- サーバーに要るのは**コードの範囲を見つける解釈だけ**で、太字などは知らなくてよい。`internal/chat/mention` に
  「コードの範囲を除いてからトークンを探す」を足す。コードの範囲の規則（決定 2 のコードブロックとインラインコード）は
  Go と TypeScript の両方に書くことになるので、**同じ入力と結果の組を 1 つの JSON にして、両方のテストから読む**
  （`testdata/format/code-spans.json`（仮））。
- Web の入力欄の変換（`toWireBody`）も、コードの中の `@handle` をトークンにしない。編集で戻す（`toInputBody`）ときも、
  コードの中はそのまま残す。
- 引用の中のメンションは除外しない。引用は「誰かの発言の写し」とは限らず、文の一部として書かれることも多い。
  引用した `@channel` で全員に飛ぶのは、送る前の確認のモーダル（ADR 0043）で止められる。

### 6. システムメッセージと既存のメッセージ

- システムメッセージは `body` が空で、文言はクライアントが作る（ADR 0033）。解釈を通さないので影響はない。
- 既存のメッセージは、次に表示したときから新しい解釈で描かれる。マイグレーションはしない。
  記号を書式のつもりなく書いていた本文（`*注意*` など）は見た目が変わるが、テキストは変わらないので、失われるものはない。

### 7. 入力欄（6.10b に回すもの）

6.10a の入力欄は textarea のまま、記号を手で打つ。ショートカットとツールバーは付けない。
6.10b の ADR で、ライブラリ（いまの推しは Lexical）、ツールバーとショートカット、IME、メンションの補完の移し替え、
16 行の上限（`--composer-max-lines`。ADR 0048）の引き継ぎを決める。**6.10b は決定 2 の記法を書き出し、この ADR の保存の形を変えない。**

## 理由

- **テキストで保存するのは、サーバーと検索に触れないため。** 本文の意味（メンション）はサーバーがトークンから決めている（ADR 0041）。
  エディタの JSON を保存すると、サーバーの解釈・`docs/events.md`・6.16 の検索（本文のテキストを引く）がすべてその形を知る必要があり、
  エディタを替えるたびに保存済みの本文を移すことになる。テキストなら、エディタは書き出すだけの部品になる。
- **mrkdwn 寄りにしたのは、Slack で慣れた打ち方がそのまま効き、メンションのトークンと同じ系統の記法に揃うため。**
  Markdown のサブセットにすると `*x*` の意味が逆（斜体）になる。
- **境界を空白ではなく「ASCII の英数字でないこと」にしたのは、日本語の文中で書式を効かせるため。**
  6.10b で入力欄が文中の一部を太字にしたとき、その結果を保存できる記法でなければならない。
  英数字だけを境界にしないので、識別子（`snake_case`）や式（`2*3*4`）は書式にならない。
- **Web で解釈するのは、表示の責任をクライアントに寄せるため。** サーバーが HTML を返すと、XSS の防御がサーバーのエスケープに
  依存し、将来のネイティブアプリには HTML が使いにくい（CLAUDE.md ルール 2 と同じ考え方）。
  サーバーが知るのは、件数に効くコードの範囲だけにする。
- **React の要素で描くのは、XSS を仕組みで防ぐため。** HTML の文字列を組み立ててサニタイズする方式は、サニタイザの設定の抜けが
  そのまま穴になる。テキストしか出ない描き方なら、エスケープし忘れが起きない。
- **コードの中のメンションを数える側でも外すのは、表示と件数を一致させるため**（ADR 0041 で約束したこと）。
  サーバーはクライアントの申告を信じない（ADR 0041）ので、除外もサーバーの解釈で行う必要がある。

## 検討した代替案

- **Markdown のサブセット（CommonMark から機能を外す）**: 仕様があり広く知られているが、`*x*` が斜体になり Slack の打ち方と逆になる。
  オーナーと比較して不採用（2026-09-21）。
- **エディタの JSON（Lexical の state など）を保存する**: 入力欄の見た目をそのまま復元できるが、サーバー・イベント・検索がエディタの形に縛られる。
  決定 1 の理由で不採用。
- **サーバーで HTML に変換して返す**: クライアントは描くだけになるが、XSS の防御がサーバーのエスケープに依存し、ネイティブアプリで使いにくい。
- **HTML の文字列を作ってサニタイズ（DOMPurify）してから埋め込む**: 既存の Markdown のライブラリがそのまま使えるが、
  サニタイザの設定が防御の要になり、依存も増える。
- **境界を空白にする**: 英文の書き方には近いが、日本語の文中で書式が効かず、6.10b の入力欄の結果を保存できない。
- **コードの中のメンションも数える（サーバーを変えない）**: サーバーはいまのままでよいが、チップにならないメンションで通知が飛ぶ。
  チップにする（コードの中でも解釈する）と、コードを書いたとおりに出すという意味が崩れる。
- **引用の中のメンションも除外する**: 引用で全員に飛ぶ事故は防げるが、文の一部としての引用で通知が来なくなる。確認のモーダルで足りる。
- **6.10 で入力欄まで作る**: オーナーと比較して、表示と入力欄を分けた（2026-09-21）。IME とメンションの補完の作り直しが重く、
  表示だけで DoD の 3 項目は満たせる。

## 結果（トレードオフ）

- **日本語の文中でも記号が書式になる。** `これは*太字*です` は太字になる。困る例は、
  日本語の文中で `*` や `_` を記号として使うとき（`※` の代わりに `*` を使うなど）。その場合はインラインコードで囲む。
- **コードの範囲の規則を Go と TypeScript の 2 か所に書く。** 共通の JSON のテストでずれを防ぐが、規則を変えるときは両方を直す。
- **既存のメッセージの見た目が変わりうる**（決定 6）。
- **6.10a の入力欄では記号を手で打つ。** 打った記号がそのまま入力欄に見える状態は 6.10b まで続く。
- 新しい API・WebSocket のイベント・マイグレーションはない。ERD と `docs/events.md` は変わらない。
  サーバーの変更は `internal/chat/mention` のコードの範囲の除外だけ。
