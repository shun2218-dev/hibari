# 0063. ブランドとページのメタデータ（タイトル・ファビコン・OGP・検索エンジン・LP）

- 状態: 採用
- オーナーの確認: 2026-09-24
- 日付: 2026-09-24

## 背景

本番のデプロイ（Phase 7 以降。ADR 0046）の前に、ブランドまわりを整えたい（オーナーの要望: 2026-09-24）。
対象は OGP 画像、ロゴ、ファビコン、ディスクリプション、アプリのタイトル、ページごとのタイトル、sitemap、robots.txt。

いまの前提は次のとおり。

- タイトルはルートの `metadata` の `"hibari"` だけで、どのページも同じ。ファビコン・OGP・robots・sitemap はない。
- ロゴはない。認証の画面（`auth-shell.tsx`）とワークスペースの切り替え（`workspace-switcher.tsx`）が文字の「hibari」を置いているだけ。
- ドメインは `hibari-chat.com`。Web は `app.`、API は `api.`、Storybook は `ui.`（ADR 0046、`docs/deploy.md`）。
- ログインの状態はブラウザ側でしか分からない。refresh の Cookie は `Path=/api/v1/auth` なので、ページを描くサーバーには届かない（ADR 0010 / 0024）。
  ルーム名やワークスペース名も、ブラウザが API から取る。
- アクティビティ（ADR 0058）の数字が、左のメニューのバッジ（`workspace-screen.tsx` の `unreadActivity`）にある。
- 見た目の正本は Claude Design から取り込んだ `docs/ui/`。そこにない画面や状態は発明しない（CLAUDE.md「デザイン」）。

### Slack で確かめたこと

オーナーが実物で確かめてくれた（2026-09-24）。

- タブのタイトルは「チャンネル名 - ワークスペース名 - N 個の新しいアイテム - Slack」。N はアクティビティの数字。
- 通知があるときは、ファビコンの右上に赤い丸が付く。数字は出ない。

### オーナーと決めたこと（2026-09-24）

- ロゴ・ファビコン・OGP 画像の絵は Claude Design で作って取り込む。この ADR は、それを受け取る側の決まりを決める。
- 検索エンジンには LP（紹介のページ）を作って載せる。LP の見た目も Claude Design で作る。
- Storybook は検索エンジンに載せない。
- タブのタイトルに、Slack と同じくアクティビティの数字を出す。チャンネル名に `#` は付けない。
- ファビコンの印は数字ではなく丸にする（Backlog と同じ）。
- ディスクリプションは下の決定 1 の文言にする。

## 決定

### 1. 名前と説明

| 項目 | 値 |
|---|---|
| アプリ名 | `hibari`（小文字。いまの文字のロゴと同じ） |
| ディスクリプション | ワークスペースとチャンネルで話す、リアルタイムチャット。 |
| `og:site_name` | `hibari` |
| `og:locale` | `ja_JP` |

ディスクリプションは LP にもアプリにも同じものを使う。ページごとに書き分けない（LP のほかは検索エンジンに載せないので、書き分ける意味がない。決定 5）。

### 2. タブのタイトルは ` - ` で区切り、最後にアプリ名

区切りは Slack と同じ ` - `。ルートの `metadata` を `title: { template: "%s - hibari", default: "hibari" }` にする。

| URL | タイトル |
|---|---|
| LP（`hibari-chat.com/`） | `hibari - ワークスペースとチャンネルで話す、リアルタイムチャット` |
| `/login` | `ログイン - hibari` |
| `/signup` | `アカウントを作成 - hibari` |
| `/forgot-password` | `パスワードを再設定 - hibari` |
| `/reset-password` | `新しいパスワードを設定 - hibari` |
| `/verify-email` | `メールアドレスの確認 - hibari` |
| `/settings` | `設定 - hibari`（モバイルの項目の一覧） |
| `/settings/<節>` | `<節の名前> - 設定 - hibari`（例: `プロフィール - 設定 - hibari`） |
| `/j/<code>` | `ワークスペースへの招待 - hibari` |
| `/w/<id>/admin/<節>` | `<節の名前> - <ワークスペース名> - hibari` |
| `/w/<id>/r/<roomId>` | `<ルーム名> - <ワークスペース名> - N 個の新しいアイテム - hibari` |
| `/w/<id>/threads` | `スレッド - <ワークスペース名> - N 個の新しいアイテム - hibari` |

- **ルーム名に `#` も鍵のアイコンも付けない。** DM は相手の表示名にする。
- **N は左のメニューのアクティビティのバッジと同じ数**（ADR 0058 の `unreadActivity`）。数え直さない。0 のときは「N 個の新しいアイテム - 」を丸ごと省く。
  数字と「個」の間には空白を入れる（「未読 3 件」「3 件の返信」と同じ書き方）。
- 左のメニュー（DM・アクティビティ・後で）はサイドバーの中身を変えるだけなので、タイトルは変えない。タイトルが指すのはメインの領域。
- 節の名前は、その画面の見出しと同じ語にする。認証の画面も同じ（`/signup` は「アカウントを作成」）。
- **追記（2026-09-24、実装）**: 表を実装に合わせて直した。
  - 認証の画面は、すでに見出しと同じ語のタイトルが付いていたので、その語のまま template の形にした（「アカウント作成」「パスワードの再設定」から変えた）。
  - `/w/<id>/saved` は「後で」の古い URL で、`?side=later` へ移すだけなので行を消した。「後で」は左のメニューなので、タイトルを変えない。
  - 検索（`?q=`）の結果はメインの領域に重ねて出すが、パスは開いていたルームのままなので、タイトルもルームのままにする。
- 固定のタイトルは各 `page.tsx` の `metadata` に書く。いまの `page.tsx` は、`app/(app)/page.tsx` と `app/(app)/settings/page.tsx` のほかはすべてサーバーのコンポーネントなので、そのまま書ける。
- 名前が要るタイトル（ワークスペース名・ルーム名・N）は、ブラウザで `document.title` に入れる（背景のとおり、描くサーバーは名前を知らない）。
  入れる処理は 1 つのフックにまとめ、組み立ては純粋な関数にしてテストする。名前が読めるまでは `metadata` の値（`hibari`）のままにする。
- `/j/<code>` のタイトルにはワークスペース名を入れない。プレビューはログインしないと読めない（ADR 0011）。そのため、名前を入れても人によって出たり出なかったりするうえ、URL を知っている人に中身を見せないという ADR 0011 の考えとも合わない。

### 3. ファビコンは「丸なし」と「丸あり」の 2 枚を差し替える

- アクティビティが 1 以上のあいだ、`<link rel="icon">` を丸ありの SVG に差し替える。0 に戻ったら丸なしに戻す。N は決定 2 のタイトルと同じもの。
- **丸は琥珀（attention）。** Slack は赤だが、hibari では琥珀が「いま起きていること」の色で、アプリの中の未読バッジも琥珀（`tokens.md`）。赤（danger）はエラーと削除の色。
  ファビコンだけ赤にすると、同じ未読を 2 色で表すことになる。
- 数字は出さない。16px では 2 桁が読めず、数字はタイトルにすでにある。
- ファビコンは画像なので CSS 変数を読めない。色は Claude Design から書き出した値をそのまま使う。トークンの値を変えたら書き出し直す（下の「結果」）。
- 置くファイル（Next.js のファイル規約）:

| ファイル | 用途 |
|---|---|
| `web/app/icon.svg` | ファビコン（丸なし） |
| `web/public/icon-activity.svg` | ファビコン（丸あり）。差し替えるときにだけ使うので、規約のファイルにしない |
| `web/app/favicon.ico` | SVG を読めないブラウザ向け（32px）。丸は付けない |
| `web/app/apple-icon.png` | iOS のホーム画面（180px） |

- タブの背景はブラウザと OS の設定で明るくも暗くもなる（hibari のテーマの設定とは関係ない）。マークはどちらの背景でも読める形にしてもらう。
- Web App Manifest（PWA）は作らない。ロードマップにないため。

### 4. OGP 画像は共通の 1 枚

- `web/app/opengraph-image.png`（1200×630）を置き、すべてのページで同じものを使う。`twitter:card` は `summary_large_image`。
- 招待リンク（`/j/<code>`）を Slack などに貼ったときも、この共通の画像とディスクリプションが出る。ワークスペースの名前や人数は出さない（決定 2 と同じ理由）。
- `og:image` などに要る絶対 URL の起点（`metadataBase`）は環境変数から取る（決定 7）。

### 5. 検索エンジンに載せるのは LP だけ。LP は `hibari-chat.com`（apex）に置く

LP は `app.` とは別のホスト、登録可能なドメインそのもの（`hibari-chat.com`）に置く。Slack の `slack.com`（LP）と `app.slack.com`（アプリ）の分け方と同じ。
同じ Next.js のアプリで描き、`web/proxy.ts` がホスト名を見て LP のルートに振り分ける。

| ホスト | 載せるか | robots.txt | ページ |
|---|---|---|---|
| `hibari-chat.com` | 載せる | すべて Allow。`Sitemap:` を書く | LP だけ。sitemap も `/` の 1 件だけ |
| `app.hibari-chat.com` | 載せない | Allow（下の理由） | すべてに `X-Robots-Tag: noindex, nofollow` |
| `ui.hibari-chat.com`（Storybook） | 載せない | `Disallow: /` | — |
| `docs.hibari-chat.com`（ドキュメントサイト） | 載せない | `Disallow: /` | ADR 0064 決定 5 |

- **`app.` を robots.txt で Disallow にしない。** Disallow は「読みに来るな」であって「載せるな」ではない。
  Disallow にすると、よそに貼られた URL だけが中身なしで検索結果に出うる。そうなると、招待リンク（`/j/<code>`）の秘密のコードが検索結果に並ぶ。
  読ませたうえで noindex を返せば、検索エンジンは URL ごと落とす。
  noindex は `proxy.ts` がホストで判断して、レスポンスヘッダで付ける。ページごとの `metadata` に書き忘れても漏れないようにするため。
- Storybook とドキュメントサイトは秘密を含まないので、読ませないだけでよい。`robots.txt` を `web/.storybook/static` などに置いて、Storybook のビルドに含める。
- `/login` や `/signup` も載せない。LP から入れるので、別に載せる理由がない。
- `www.hibari-chat.com` は作らない。

### 6. ロゴ・ファビコン・OGP 画像・LP は Claude Design で作る

Claude Design に頼むもの:

1. ロゴ: マークとワードマーク。ライトとダークの 2 版
2. ファビコン: 丸なしと丸あり（決定 3）。16px でもつぶれない形にする
3. OGP 画像: 1200×630 の 1 枚
4. LP: デスクトップ（1280 幅）とモバイル（390 幅）。ライトだけ（下の理由）

- 取り込んだら、画面仕様と同じく `docs/ui/` にスクリーンショットを置き、`docs/ui/README.md` に節を足す。
  書き出したファイルは `docs/ui/brand/` に元の SVG を残し、`web/` にコピーする。
- 文字の「hibari」をロゴに置き換える（`auth-shell.tsx`、`workspace-switcher.tsx`）のは、Claude Design 側の画面を直して、スクリーンショットを撮り直してから行う。
- **LP はライトだけにする。** テーマの設定は `app.` の localStorage にあり（`lib/theme.ts`）、オリジンの違う apex からは読めない。
  LP のためだけにテーマの受け渡しを作るほどの価値はない。

### 7. 絶対 URL の起点は環境変数

| 変数 | ローカル | 本番 | 使う所 |
|---|---|---|---|
| `APP_BASE_URL`（既存） | `http://localhost:3000` | `https://app.hibari-chat.com` | アプリの `metadataBase`、LP からログインへのリンク |
| `SITE_BASE_URL`（新規） | `http://lp.localhost:3000` | `https://hibari-chat.com` | LP の `metadataBase`・canonical・sitemap・robots の `Sitemap:`。`proxy.ts` が LP に振り分けるホスト |

- ローカルでは `lp.localhost` で LP を開く（`*.localhost` はループバックに解決される）。
- `docs/deploy.md` に `SITE_BASE_URL` の節と、apex のドメインを Fly の Next.js のアプリに向ける手順を足す。

## 理由

- **LP を apex に置く**:
  - `app.` の `/` は、いまのまま「ログインした後の入口」にしておける。同じ `/` に LP を置くと、LP は検索エンジンのためにサーバーで描く必要がある。
    ところがログインの状態はブラウザでしか分からないので（背景）、ログイン済みの人は開くたびに LP が一瞬見えてからアプリに移る。
    それを避けるにはアプリの入口を別の URL に移すことになり、いまのリダイレクトやリンクを全部直すことになる。
  - 載せるか載せないかをホストで分けられる。`app.` は全部 noindex、apex は全部 index で、ページごとの判断が要らない。
- **noindex をヘッダで付ける**: 招待リンクを載せないことは、秘密を守る話である。ページを足すたびに `metadata` に書くことを覚えている、という運用に頼らない。
- **ファビコンを 2 枚の静的なファイルにする**: 数字を出すなら、件数が変わるたびに canvas で描き直すことになり、書体の読み込みを待つ処理と、そのテストが要る。
  丸なら `href` を差し替えるだけで済む。

## 検討した代替案

- **LP を `app.hibari-chat.com/` に置く**: DNS もホストの振り分けも要らない。ただし、ログイン済みの人にも LP が一瞬見える（理由のとおり）。
  アプリの入口を `/home` などに移せば避けられるが、影響が大きい。
- **LP を別のアプリ（静的なサイト）にする**: Fly のアプリが 1 つ増える。デザインのトークン（`globals.css`）と書体を 2 か所で持つことになる。
- **`/login` と `/signup` も検索エンジンに載せる**: LP があれば要らない。載せても検索する人がいない。
- **`app.` を robots.txt で Disallow にする**: 決定 5 のとおり、招待リンクの URL だけが検索結果に出うる。
- **ファビコンに数字を出す**: 決定 3 と理由のとおり。Slack も丸。
- **丸を Slack と同じ赤にする**: 決定 3 のとおり、アプリの中の未読（琥珀）と色が割れる。
- **タイトルのルーム名に `#` を付ける**: オーナーの判断で付けない（2026-09-24）。

## 結果（トレードオフ）

- ファビコンの丸の色は、CSS 変数ではなく書き出したファイルの中の値になる。`--color-attention` を変えたら、ファビコンも書き出し直す。
  CLAUDE.md の「トークンの正本は `globals.css` だけ」の例外になるので、`docs/ui/tokens.md` に書いておく。
- `favicon.ico` には丸が付かない。SVG のファビコンを読めないブラウザでは、アクティビティがあることがファビコンで分からない（タイトルでは分かる）。
- apex にも証明書と DNS の設定が要る。`proxy.ts` のホストの振り分けと、ローカルの `lp.localhost` が増える。
- LP にダークの見た目はない。
- ワークスペース名とルーム名は、ブラウザのタブと履歴に残る（Slack も同じ）。

## オーナーと確定した内容（2026-09-24）

下の項目はすべて案のまま採用。

1. LP を apex（`hibari-chat.com`）に置く（決定 5）。`app.` の `/` に置く案もある（検討した代替案）。
2. `app.` は `/login` と `/signup` も含めて、すべて検索エンジンに載せない（決定 5）。
3. ファビコンの丸を琥珀にする（決定 3）。Slack は赤。
4. LP はライトだけ（決定 6）。
5. 決定 2 の表のタイトル。特に、DM は相手の表示名、`/j/<code>` にはワークスペース名を入れない、の 2 点。

## 実装の順序

1. **この ADR**（オーナーの確認）← 完了
2. Claude Design でロゴ・ファビコン・OGP 画像・LP を作り、`docs/ui/` に取り込む
3. タイトル: `metadata` の template と各ページの固定のタイトル。名前と N を入れるフックと、組み立てる純粋な関数。テスト

5. ファビコン・OGP 画像・ロゴの置き換え（2 のファイルが要る）。ファビコンの差し替えのテスト
6. LP（2 の画面が要る）
7. `docs/deploy.md` に `SITE_BASE_URL` と apex の DNS を足す
